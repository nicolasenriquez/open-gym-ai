# HTTP API

The public Python HTTP API, with auth,
request/response schemas and the env-dependent behavior — is documented as a
hand-written OpenAPI 3.1 spec:

- **Canonical API document:** [`backend/openapi.yaml`](../backend/openapi.yaml)
- **Browsable static reference:** https://opengym.ch/api.html

The Python handlers and their behavioral tests establish the
implemented behavior. Keep the specification aligned with them; a discrepancy
needs investigation, not an automatic change to either contract. The website
reference is generated by `scripts/build-api-docs.mjs`, without Swagger UI.

Lint it after changing routes:

```sh
pnpm dlx @redocly/cli lint backend/openapi.yaml
```

## Python platform API v1

The partial Python port uses `/api/v1` exclusively, including its internal
health probes. Unversioned paths have no aliases or redirects. See the
[backend HTTP contract](../backend/README.md#http-api-v1) for frontend build
selection, available capabilities and probe visibility.

The canonical YAML uses `/api/v1`; Node still serves `/api`. Its frozen historical
contract is retained under `backend/contracts/node-openapi.v1.yaml` for transition
verification, not as an editable specification. Internal live/ready probes are
omitted from the public YAML. Python does not expose Swagger, ReDoc or an HTTP
OpenAPI endpoint. Run `node scripts/platform.mjs verify contracts --case python_routes`
for the router and HTTP response check; capability suites cover authenticated
success, errors, cookies and persistence in more detail.
