# Independent qualitative assessment A (recorded before detector)

⚠️ DEGRADED: single-context (no sub-agent tool exposed). Methodology adapted from installed Impeccable critique/audit; not an unmodified command run. No overlay injection or external service.

Target: existing openGym source at v1.4.0 and HEAD v1.4.1, runtime localhost:8080 reporting v1.4.1. Operate mode.

The product has a coherent, deliberately restrained mobile-operating language: inset settings groups, hairlines, regular text, system icons, conspicuous start/resume and a quieter session view. Calendar, muscle map and set grid make it domain-specific rather than an interchangeable dashboard. Desktop expansion preserves the mobile model rather than inventing a sidebar. These are strengths to preserve.

Priority investigations before any normative design specification:
1. Sheet focus is left on the background exercise opener; pressing Tab focuses its background Plan button. No dialog semantics on shared sheet. Escape works. Keyboard/screen-reader containment needs investigation, not silent preservation as an approved pattern.
2. Light green accent text is visibly weak on light surfaces; low-alpha helper text is also faint. Measure actual pairs. CSS's claim that 17px/600 is WCAG large text is suspect (17px is below the 18.67px bold threshold).
3. Settings switches appear unnamed in accessibility snapshots despite adjacent visible labels. Verify their accessible names before attributing a failure.
4. Design principles exist but no reusable typography scale survives; explicit comments explain its removal as a design decision. Do not recreate one as cleanup.
5. Version provenance prevents calling the screenshots v1.4.0 evidence. Source can still be extracted accurately with git show.

Cognitive load: Home has one prominent welcome action and task groups. Library intentionally exposes three horizontal filter strips; more than four choices is not independently a defect in a searchable catalogue. Settings progressively discloses domains and has search. One exercise's actions are gathered behind a menu; preserve discoverability/accessibility alternatives. No abandonment or performance claims can be inferred from screenshots.

Personas: Sam (keyboard/screen reader) encounters background sheet focus and unnamed controls; Casey (one-handed mobile) benefits from bottom Start and docked rest but narrow clear/filter controls require measured hit testing; Jordan (first-time guest) gets an explicit welcome and local-data banner but exercise descriptions may fall back to English.

No global numerical health score: authenticated flows, populated analytics, native touch, assistive technology and long-history performance are not verified. Questions retained for the product owner in 06-open-questions-and-plan.md; no implementation authorized.
